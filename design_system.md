# Design System — ревью и карта внедрения

Дизайн-система пришла как **HTML/CSS/JS прототип** от Claude Design (handoff-bundle), не как markdown-брифл. Все исходники — в `design/` в корне проекта:

- `design/README.md` — инструкция handoff'а
- `design/chats/chat1.md` — полная переписка с дизайнером
- `design/project/tokens.jsx` — палитры трёх тем, шрифты, плотности
- `design/project/ui.jsx` — компонентный словарь (Card, Button, Row, Chip, Sparkline, …)
- `design/project/screens.jsx` — 10 экранов (Dashboard, Calendar, CreditCard, Loan, Savings, Debit, History, AddTx, Profile, BottomSheet)
- `design/project/data.jsx` — мок-данные, на которых нарисованы экраны
- `design/project/index.html` — сборка-монтаж с TabBar и приложением
- `design/project/icons.jsx`, `ios-frame.jsx`, `design-canvas.jsx`, `tweaks-panel.jsx` — вспомогательные

Этот документ — **не дизайн-бриф** (его нет), а моя сводка того, что в бандле, плюс выписка противоречий со спекой и нашей реализацией.

## 1. Что получилось в дизайне (финальная версия после итераций)

По переписке (`design/chats/chat1.md`):
1. Стартовал как 3 разных направления (Atlas / Meridian / Terminal).
2. Пользователь (ты) попросил: «это приложение для моих финансов, не банковское — убрать пополнить/вывести/оформить карту/пригласить друга/кэшбэк/QR».
3. Пользователь попросил: «сохраним все три темы, но стиль оставим от варианта Pulse + переключатель тем в настройках + большой макет».
4. Финал: 3 темы = палитры, один общий layout (Pulse = dark + editorial), теми переключаются в профиле.

### 1.1 Палитра (из `tokens.jsx`)

Все три темы шарят один layout: `radius: 16`, `radiusLg: 24`, `radiusSm: 10`, density `comfortable`, borderStyle `soft`, displayFont `Geist 500`.

Отличаются только цвета:

| Тема | Name | Mode | bg | surface | accent | pos / neg | Настроение |
|---|---|---|---|---|---|---|---|
| **A** | Paper | light | `#f4f0e8` тёплый кремовый | `#faf7ef` | `#1f5f3a` ledger-green | `#1f5f3a` / `#a8351c` | бумажная тетрадь |
| **B** | Pulse | dark | `#14100c` тёмный жжёный | `#1e1812` | `#ff7a47` sunset coral | `#9adb7a` / `#ff7a47` | calm modern |
| **C** | Noir | dark | `#0c0e0d` почти чёрный | `#14171a` | `#7be5b3` mint | `#7be5b3` / `#ff8a70` | CRT phosphor |

Семантика: `text/text2/text3/text4` (4 уровня яркости), `hairline/hairline2` (2 уровня границ), `accentDim` (приглушённый tint для hover/selected).

Используется во всех трёх темах (единый layout).

## 2. Противоречия со спекой (§7) и нашей моделью (`lib/db/schema.ts`)

### 2.1 Модель данных

| Что | В дизайне | В спеке / схеме | Решение |
|---|---|---|---|
| `balance` | signed (`-48_240` для долга) | положительный kopecks + type-aware смысл | берём нашу; UI рендерит знак по `account.type` |
| `last4` маска карты | есть на всех счетах | нет | **вопрос**: добавить optional `last4` на `accounts`? для savings/loan — странно |
| `spark` (массив тренда) | хранится в данных | не хранится | **вычислять** из `transactions` за N дней или убрать спарклайны |
| `graceAmount` / `graceDate` | готовые числа | `statementDebt`, `paidAfterStatement`, `lastStatementDate` + `paymentDueDay` | `toCloseGrace` и `nextPaymentDueDate` уже есть в `CreditCardEngine` |
| `CATEGORIES` с `limit`/`color` | статический массив | нет таблицы категорий | **вопрос**: добавить таблицу `categories`? v1.1 по §9 |
| `forecastBalance()` c `Math.random()` | шумовой дневной drift | `ForecastEngine` детерминирован | берём наш |

### 2.2 Экраны vs §7 спеки

| §7 экран | Дизайн | Gap |
|---|---|---|
| §7.1 дашборд | net worth + cashflow warning + accounts + categories | **нет «ближайших 3 события»** (требование спеки) |
| §7.2 add операция | полноэкранная форма + bottom-sheet быстрого ввода | OK, даже шире спеки |
| §7.3 кредитка | grace card + stats + history | **нет кнопок** «Погасить грейс / Внести мин.платёж / Создать трату» |
| §7.4 кредит | досрочка-слайдер + debt structure | **нет кнопок** «Оплатить платёж / Редактировать»; **нет графика платежей (таблицы)** |
| §7.5 календарь | 2-month grid + chart + hero | ✓ полностью покрывает |
| §7.6 события (регулярные) — список, CRUD, история | **нет экрана**, только ссылка «Регулярные платежи · 8 запланированных» в профиле (в никуда) | **надо построить** screen'ы |
| §7.7 настройки | профиль есть, но **нет редактора настроек карты/кредита** | **надо построить** (лимит, ставка, платёж) |

### 2.3 Данные дизайна vs наши seed-значения

В `data.jsx` дизайнер «довыдумал» цифры (с твоего разрешения в чате). Они не совпадают с тем, что ты давал как seed:

| Поле | Дизайн | Спека / твои seed | Источник истины |
|---|---|---|---|
| loan rate | 19.9 % | 36.5 % | твои |
| loan principal | 500 000 ₽ | 350 000 ₽ | твои |
| loan termMonths | 48 | 59 | твои |
| loan payment | 12 840 ₽ | 12 840 ₽ | совпадает |
| creditCard debt | 48 240 ₽ | 26 500 ₽ | твои |
| дебет старт | 147 820 ₽ | спросить у тебя (висит с шага 3) | твой ответ |

Финальный UI рендерится на **наших seed**, не на дизайн-моках.

### 2.4 Архитектурные расхождения

| Что | Дизайн | У нас | Решение |
|---|---|---|---|
| Тёмная тема | 3 темы + переключатель в профиле | hardcoded `<html className="dark">`, отказ от `next-themes` на шаге 1 | **переделать**: CSS vars для 3 тем + switcher. Persist: cookie (серверные RSC видят тему) |
| Default theme | в дизайне показан `A` (Paper, light) | ты просил «dark-first» | предлагаю **Pulse (B)** как default |
| Font loading | `Geist` + `Geist Mono` из Google | Geist подключён через `next/font` (cyrillic) | Geist Mono добавить в layout |
| UI-фундамент | свой inline-styles + проп `t` (токены) | shadcn/ui (radix + Tailwind v4 css vars) | **keep shadcn**, перекрасим CSS vars в `app/globals.css` под design palette; добавим недостающие primitives (Row, Stat, Chip, Segmented, Sparkline, NumberPad) в `components/ui/` как Tailwind-обёртки |
| Навигация | push-based (`nav.go`) + TabBar в корне | Next App Router (`/`, `/calendar`, `/add`, …) | адаптировать: TabBar = навигация по базовым путям; screens внутри tab = сегменты |
| Mock data | фейк из `data.jsx` | server actions из шага 7 | заменяем — список/чтение через RSC + `listAccounts`/`listTransactions`, мутации через server actions |
| iOS frame | оборачивает каждый экран | у нас просто responsive | сносим iOS-frame, рендерим mobile-first layout в браузере |

## 3. Пробелы в дизайне (экраны / функции, которых нет)

1. **§7.6 регулярные события** — список, CRUD, история исполнений, резолюция фактов (подтвердить / изменить сумму / пропустить). В дизайне пусто.
2. **§7.7 настройки счёта** — редактор `creditCardSettings` (лимит, ставка, дни) и `loanSettings` (ставка, платёж, день). В дизайне пусто.
3. **Создание нового счёта** (debit/savings/creditCard/loan с заполнением settings) — в дизайне пусто.
4. **`/login`** (у нас уже есть, сырой) — брендировать под design tokens.
5. **Логаут UI-поток** — в профиле кнопка «Выйти» без обработчика; подключить `signOut` из `@/lib/auth/config`.
6. **Onboarding / первый запуск** — ввод стартовых балансов, дата выдачи кредита и т.д. (те «висящие» seed-вопросы из плана). В дизайне пусто.
7. **Error / empty states** — нет состояний «нет счетов», «ошибка загрузки», «валидация формы».
8. **Loading states** — server actions асинхронные; skeletons/spinners не спроектированы.
9. **Модалки подтверждения** — «удалить счёт», «подтвердить платёж» — не спроектированы.

## 4. Неоднозначности / спорные решения дизайнера

1. **«Скрыть балансы на главной»** toggle — не описано в спеке. Добавлять?
2. **«Уведомления · Push + email · ежедневный отчёт»** — спека §9 v1.1 говорит «Пуши о дедлайнах». В web push = PWA + SW + VAPID; email = SMTP. **Скорее всего откладываем до v1.1**.
3. **«Экспорт данных · CSV · PDF»** — спека §7.7 «JSON». Делать оба формата или только JSON?
4. **Спарклайны** на дашборде и в AccountRow — откуда данные? считать из transactions (30 дней)? Или оставить placeholder?
5. **Категории-бюджеты (с `limit`)** — это v1.1 «аналитика», не v1.0. **Предлагаю скрыть блок до v1.1**.
6. **Валюта** — дизайн только ₽. Мультивалюта спекой не предусмотрена. OK.
7. **Day-pickers для прошлых дат** — в календаре можно тапнуть прошлые дни; показывать баланс тогда = берём из факта (txs) или говорим «в прошлом»?
8. **iOS-specific** («•• 4821» маска, «‣ Пн Вт Ср») — в web ок, но без ощущения «приложения». Не критично.

## 6. Предлагаемая карта имплементации (после твоего ок)

1. **Темизация**: переписать `app/globals.css` — три `@layer base { :root.paper / :root.pulse / :root.noir }` с oklch-palette из `tokens.jsx`; `next-themes` ставим; dark-first = Pulse.
2. **Шрифты**: Geist + Geist Mono в `app/layout.tsx` через `next/font`; CSS vars `--font-sans` / `--font-mono`.
3. **Tailwind токены**: маппинг семантических → CSS vars (`--bg`, `--surface`, `--surface2`, `--text`, `--text2`, `--accent`, `--accent-dim`, `--pos`, `--neg`, …). Все компоненты будут использовать `bg-surface text-foreground` и т.д.
4. **UI primitives** (`components/ui/`): переработать shadcn `Button` под design (sm/md/lg, primary/secondary/ghost/danger); добавить `Card`, `Row`, `Stat`, `Chip`, `Segmented`, `Progress`, `Sparkline`, `NumberPad`, `IconTile`, `TabBar`.
5. **Layout**: `app/(app)/layout.tsx` с `TabBar` в фиксированном низу, `Header` сверху; брендированный `/login`.
6. **Роуты**: `/` (dashboard), `/calendar`, `/accounts/[id]` (dispatch по type → debit/cc/loan/savings views), `/add`, `/history`, `/profile`, плюс `/events` (CRUD регулярных), `/accounts/[id]/settings`.
7. **Данные**: каждый экран RSC → `listAccounts()` / `listTransactions()` / `listEvents()` / `runForecastAction()`; мутации через server actions из шага 7.
8. **Onboarding / seed-первый запуск**: если у юзера 0 счетов — редиректим на `/onboarding`, заполняем стартовое состояние по §8 спеки.
9. **Theme switcher в профиле** + логаут через `signOut`.
10. **Smoke**: `tsc`, `lint`, `build`, `vitest`; мануальная проверка главных потоков в браузере.

Всё это будет разбито на подшаги, после каждого — «ок, дальше».
