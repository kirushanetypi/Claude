# ТЗ для Claude Design — Десктопная версия finance-web

> **Адресат**: Claude Design (claude.ai/design).
> **Цель**: спроектировать десктопную (md/lg/xl) версию приложения личных финансов на базе уже существующей мобильной — не переделывать, а **расширять**.
> **Текущее состояние**: мобильная версия в `design/` (handoff-bundle), описана в `design_system.md`. Спека продукта — `finance_app_spec.md`. Кодовая реализация — Next.js 16 + React 19 + Tailwind v4 + shadcn/ui.

---

## 0. TL;DR

Сделай `≥1024px` layout, который:

1. **Сохраняет визуальный язык** мобилки (3 темы Pulse / Paper / Noir, Geist + Geist Mono, единые токены, тот же тон цифр и эйбров).
2. **Заточен под мышь и клавиатуру** — а не под палец. Hover-состояния, контекстные меню по правой кнопке, фокус-рамки, полная hotkey-карта.
3. **Спроектирован под массовый ввод данных** — добавить 30 транзакций за минуту реально (paste-grid, batch-form, inline editing в таблице, авто-комплит категорий).
4. **Имеет расширенную аналитику** — отдельный раздел `/analytics` с дашбордами по cashflow, категориям, счетам, прогнозу, сравнением периодов.

Мобильная версия остаётся источником истины для токенов и компонентов; десктоп — это **новые лейауты + новые экраны**, не редизайн.

## 1. Контекст и ограничения

### 1.1 Что есть
- Стек: Next.js 16 App Router, React 19, Tailwind v4 (CSS variables), shadcn/ui (Radix), drizzle + better-sqlite3, auth.js v5, decimal.js (деньги в копейках, integer).
- 3 темы: **Pulse** (B, dark, coral) — default; **Paper** (A, light, ledger-green); **Noir** (C, dark, mint).
- Шрифты: Geist (sans), Geist Mono (числа, лейблы, табличные данные).
- Радиус: 16 (карточки), 24 (большие), 10 (компактные). Density `comfortable` (rowY=16, rowX=18, gap=12).
- Mobile экраны: Dashboard, Calendar, Add, History, Profile + Accounts (Debit/CC/Loan/Savings) + Events + Settings.
- Все цифры — `tabular-nums Geist Mono`. Знаки `+` / `−` цветом (pos / neg).

### 1.2 Что нельзя ломать
- Дизайн-токены (палитры, типографика, радиусы) — наследуются 1:1.
- Семантика счёт-типов: `debit`, `savings`, `creditCard`, `loan`. Балансы у `creditCard`/`loan` хранятся как положительные kopecks, знак отображается логикой.
- Названия экранов и сущностей (Запланированные, Календарь, История, Кредитка, Кредит, Накопительный, Дебет).
- Расчётная модель: ForecastEngine, CreditCardEngine, LoanEngine — детерминированные, без рандома.

### 1.3 Чего не делаем в этом ТЗ
- Не проектируем мобильную версию (она готова).
- Не делаем приложение «банк» (нет «пополнить картой», «оформить», «пригласить друга», «кэшбэк», «QR»).
- Не вводим мультивалюту, переводы между юзерами, инвестиции, бюджеты-цели поверх категорий (всё это вне scope v1.0).
- Не проектируем мобильное приложение под iOS/Android — это веб.

## 2. Адаптивность и breakpoints

| Bp | Ширина | Назначение | Layout |
|---|---|---|---|
| `sm` | < 640 | Мобилка (готова) | Stack, TabBar внизу |
| `md` | 640–1024 | Планшет / узкий ноут | **Гибрид**: TabBar остаётся, но карточки становятся 2-колоночными там, где есть смысл (dashboard hero + cashflow рядом) |
| `lg` | 1024–1440 | Десктоп **базовый** — целевой для ТЗ | Sidebar слева 240px + main content + правая панель 320px (контекстная) |
| `xl` | 1440–1920 | Большой десктоп | Тот же layout, +max-width 1440px main content, отступы по 80px |
| `2xl` | ≥ 1920 | Wide / 4K | Контент держит 1440px, фон тянется |

**Минимум для desktop-версии**: 1280×800. Ниже — мобильный layout с расширенным контентом, не «сломанный desktop».

## 3. Глобальный layout (≥1024px)

```
┌──────────────────────────────────────────────────────────────────┐
│ TopBar  [logo]  [breadcrumbs]   ⌘K [search]    [theme] [user]    │  56px
├────────────┬───────────────────────────────────┬─────────────────┤
│            │                                   │                 │
│  Sidebar   │        Main content area          │  Context panel  │
│   240px    │           (router outlet)         │      320px      │
│            │                                   │  (collapsible)  │
│            │                                   │                 │
└────────────┴───────────────────────────────────┴─────────────────┘
```

### 3.1 TopBar (56px, sticky)
- Слева: лого (`Pulse · Финансы` mono lockup) → клик в `/`.
- Центр: breadcrumbs (`Главная / Кредитка / Тинькофф`). Без слешей-разделителей, через `›` (mono).
- Правая часть: command palette trigger `⌘K` (видимая кнопка с подсказкой шортката), переключатель темы (3 свотча инлайном), аватар → меню.
- Высота строго 56px, фон `--bg`, нижняя hairline.

### 3.2 Sidebar (240px, collapsible до 64px)
- Разделы:
  1. **Главная** (`/`) — иконка home
  2. **Календарь** (`/calendar`) — иконка calendar
  3. **Аналитика** (`/analytics`) — иконка bar-chart **(новый раздел)**
  4. **История** (`/history`) — иконка clock-rewind
  5. **Запланированные** (`/events`) — иконка repeat
  6. ─── divider ───
  7. **Счета** — раскрывающаяся группа со списком счетов (`/accounts/[id]`), у каждого мини-баланс справа mono
  8. ─── divider ───
  9. **Быстрый ввод** (`/add`) — primary CTA, кнопка-плитка с иконкой `+` и подсказкой `N`
  10. **Импорт** (`/import`) — иконка upload **(новый раздел)**
- Внизу sidebar: версия + ссылка «Что нового» (changelog).
- Сжатый режим (64px): только иконки, тултипы при hover, активный раздел подсвечен `accent-dim`.
- Активный раздел: левая полоска 2px `--accent`, фон `--surface-2`, текст `--foreground`.

### 3.3 Main content
- Max-width 960px (на `lg`) / 1120px (на `xl`).
- Padding: 32px по горизонтали, 24px сверху.
- Содержит экран — заголовок (h2 22px), вспомогательные controls справа от заголовка, далее основной контент.

### 3.4 Context panel (320px, справа)
- **Collapsible**, hotkey `[` / `]` для скрытия/раскрытия.
- Содержимое зависит от экрана:
  - Dashboard → «Ближайшие события» + «Алерты cashflow».
  - Account → «Быстрые действия» + «Связанные транзакции».
  - History → «Фильтры» (счета, категории, диапазон дат).
  - Analytics → «Параметры периода» + «Сравнение».
  - Add → «Последние операции» (для копирования в новую).
- Если контента нет — панель свёрнута по умолчанию.

## 5. Целевой пользовательский путь (десктоп)

> «Я сел за ноут, открыл вкладку, и за 5 минут внёс все траты за неделю».

1. `Cmd+K` → набирает `пят` → выбирает «Пятёрочка» из последних → форма `/add` префилится категорией «Продукты», счётом «Альфа Дебет», датой = вчера.
2. Tab Tab — сумма 540, Enter — сохранено.
3. Стрелка ↑ — готовая форма с тем же счётом и категорией; вводит следующее.
4. Когда транзакций много (импорт выписки) — `/import` → вставить CSV в текстовое поле → preview-grid с маппингом колонок → bulk save.
5. Аналитика по результату месяца — `/analytics/categories`, фильтр «апрель», сравнение «март».

Этот сценарий — **первый класс** UX. Всё остальное (просмотр, редактирование, удаление) подчинено ему по приоритету.

#### 6.3.1 Cashflow `/analytics/cashflow`

**Цель**: понять «куда уходят и откуда приходят деньги», увидеть тренд месяц-к-месяцу.

**Layout:**

```
┌────────────────────────────────────────────────────────────┐
│ KPI-лента: 4 stat — Доход / Расход / Net / Saving rate      │
├────────────────────────────────────────────────────────────┤
│ Bar chart: доходы (зелёные) vs расходы (красные) по месяцам│
│ + line: net cumulative (накопленное сальдо)                │
├────────────────────────────────────────────────────────────┤
│ 2 кол: [Источники дохода]   [Куда уходят расходы]          │
│        (топ-5 категорий)    (топ-5 категорий с долями)     │
└────────────────────────────────────────────────────────────┘
```

**KPI-лента:**
- 4 stat-плашки: `eyebrow` + `display 32 mono` + `Δ` к предыдущему периоду (стрелка ↑ зелёная / ↓ красная).
- Saving rate = `(income − expense) / income * 100%` (с округлением до 0.1%).

**Bar chart:**
- 12 месяцев по умолчанию (или выбранный период).
- Grouped bars: доход (`--pos`) и расход (`--neg`), ширина бара 18px, гэп 8px.
- Поверх — line `net cumulative` другим цветом (`--accent`).
- Hover на месяце → tooltip с тремя цифрами + Δ к прошлому году.
- Click на месяц → переход в `/history?month=...`.

**Источники дохода / Куда уходят расходы (2 колонки):**
- Список Row-ов с прогресс-барами:
  - Иконка категории + название + mono сумма + `subtitle` процент.
  - `<ProgressBar />` под суммой шириной 100%, заполнен пропорционально топу.
- Hover row: фон `--surface-2`.
- Click row → `/analytics/categories?cat=...` с уже выставленным фильтром.

**Состояния:** период без данных → empty с подсказкой «Импортируйте операции».

#### 6.3.2 Категории `/analytics/categories`

**Цель**: глубоко изучить расходы/доходы по категориям, сравнить с прошлыми периодами, увидеть тренды.

**Layout:**

```
┌──────────────────────────┬─────────────────────────────────┐
│ Donut chart (расходы)    │ Список категорий (sortable)     │
│ 320×320, hover-segments  │ Колонки: иконка / название /    │
│ click-to-filter          │ кол-во / сумма / Δ% / тренд     │
│                          │ (sparkline) / доля% / progress  │
└──────────────────────────┴─────────────────────────────────┘
┌────────────────────────────────────────────────────────────┐
│ Detail panel при выборе категории:                          │
│ • Top-line: имя + сумма + Δ + период                       │
│ • Stacked area: динамика по дням                            │
│ • Список последних транзакций категории (5–10) + linkAll    │
└────────────────────────────────────────────────────────────┘
```

**Donut:**
- Сегменты только по расходам (toggle «Доходы / Расходы» сверху).
- Цвета — детерминированные хеши имени категории (стабильные между загрузками); рамка 2px цвета `--bg`.
- Hover сегмент: затемнение остальных, tooltip mono с суммой и долей.
- Click сегмент = выбор категории, открывает detail panel.
- В центре donut — `display 28` сумма выбранной категории (или «всё», если ничего не выбрано).

## 7. Методология аналитики (формулы и источники данных)

Все суммы — целые kopecks (`integer`). Все проценты округляются до 0.1%. Все периоды — UTC по умолчанию, отображение в локальной TZ.

### 7.1 Источники

| Источник | Что даёт |
|---|---|
| `transactions` | Факты — income/expense/transfer/loanPayment/interest. |
| `accounts` | Текущие балансы, settings (rate, limit). |
| `events` (scheduled) + `event_facts` | План + «выполнено / пропущено / изменено». |
| `ForecastEngine` | Прогноз баланса по дням на основе текущего баланса + плана. |
| `CreditCardEngine` | Грейс, минимальный платёж, нач. процентов. |
| `LoanEngine` | Расчёт основной/процентной части, остаточный срок. |

### 7.2 Cashflow

```
income(period)   = Σ transactions where type='income' AND date in period
expense(period)  = Σ transactions where type='expense' AND date in period
                 + Σ transactions where type='loanPayment' AND date in period (тело + проценты)
net(period)      = income − expense
saving_rate      = net / income * 100  (если income > 0, иначе null)
turnover         = income + expense    (общий оборот)
```

**Переводы между своими счетами не считаются ни доходом, ни расходом** — обнуляются на агрегатах. Но в drill-down показываем как «move».

**Δ к предыдущему периоду** — относительное изменение `(curr − prev) / |prev| * 100%`. Если `prev = 0` и `curr ≠ 0` — показываем `+∞` иконкой ↑.

### 7.3 Категории

```
spent_by_cat(cat, period) = Σ transactions where type='expense' AND category=cat
share_by_cat(cat, period) = spent_by_cat(cat) / total_expense(period) * 100
```

- Сортировка по умолчанию — по сумме desc.
- `Δ%` к прошлому периоду — относительное.
- Sparkline 14d — `daily_sum(cat) for last 14 days`.

**Подкатегории** в v1.0 не поддерживаются. Все категории — плоские. Stacked area в Detail panel показывает разбивку по счетам, не подкатегориям.

### 7.4 Счета

```
current(acc)        = accounts.balance (с учётом sign-логики типа)
avg_balance(period) = Σ daily_balance(d) / N_days   (daily_balance — баланс на конец дня)
min_balance(period) = min daily_balance
max_balance(period) = max daily_balance
delta_period        = current − balance_at_start_of_period
turnover(acc)       = Σ |amount| where transaction touches acc
health(acc):
  green   = avg_balance > 0 AND no day balance < 0 in period
  yellow  = had days < 0 in last 30d
  red     = forecast has days < 0 in next 30d
```

Для cc/loan — health-логика инвертированная: «зелёный» = долг сокращается; «красный» = просрочка / не успеть в грейс.

### 7.5 Прогноз

`ForecastEngine` уже даёт series `dateMs → balanceMap`. Аналитика поверх него:

```
expected_balance(at)        = forecast.balanceMap.get(account_id) at horizon
min_balance_in_horizon       = min over forecast.series of balance(account_id)
max_drawdown                 = max(0, balance_at_start − min_balance)
days_negative_in_horizon     = count of days where balance < 0
projected_saving_at_horizon  = expected_balance(horizon) − current(account_id)
```

**Что-если**: клиентский overlay поверх series — пересчёт детерминированный, без обращения к серверу (используем тот же `ForecastEngine` бандлом на клиенте, либо exposed pure function).

### 7.6 Что хранить, а что считать на лету

- На лету (read-time): всё в §7.2–7.5 для отображения.
- Кэш на сервере (Next.js `unstable_cache` или RSC + revalidatePath на мутации): агрегаты по месяцам — `monthly_summary(user, month)`.
- Никаких pre-computed таблиц в БД для v1.0 — данные мелкие (≤ 100k транзакций на юзера), всё считается за <100ms.

### 7.7 Локализация чисел и дат

- Числа: `formatRubles(kopecks)` уже есть в `lib/money.ts`. Использовать его.
- Даты: `fmtDate`, `fmtMonthYear`, `fmtTime` из `lib/dates.ts`.
- В таблицах History и в Inline edit — формат суммы `1 234,56` (русский), но при копировании — `1234.56` (machine-readable).

## 10. Массовый ввод данных (deep dive)

### 10.1 Paste-grid

**Самый важный механизм для десктопа.** Юзер копирует таблицу из Excel / банковского интерфейса / CSV → вставляет → видит preview → корректирует маппинг → импортирует.

**Парсер:**
- Делитель: автоматически (tab > `;` > `,`).
- Десятичный разделитель: `.` или `,` (определяется по первой числовой ячейке).
- Тысячный разделитель: пробел или `,` (если десятичный — `.`).
- Знак минуса: `-`, `−` (Unicode), `()` вокруг суммы (бухгалтерский формат), отрицательность по колонке «Тип».

**Угадывание колонок** (heuristics):
- Дата: первая колонка с парсимым датой (в любом формате `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY`).
- Сумма: колонка где >70% значений — числа.
- Тип: колонка с малым cardinality (income/expense/credit/debit/+/−).
- Title: колонка с самым длинным средним текстом.
- Category: колонка с малым cardinality и текстом.
- Account: dropdown — выбирает юзер один раз для всего батча.

**Preview таблица:**
- Header: dropdown «Какое поле?» на каждой колонке.
- 50 первых строк показываем; остальное — счётчик.
- Подсветка: зелёные строки = валидны; красные = ошибка с tooltip; жёлтые = warning (дубликат).
- Inline edit ячеек прямо в preview (на случай мелких опечаток).

### 10.2 Batch form

- Таблица 5-10 пустых строк, каждая = транзакция.
- Колонки: Date / Type / Account / Category / Title / Amount / Note.
- `Tab` между ячейками внутри строки, `Enter` — следующая строка (создаёт новую если последняя).
- Auto-fill по соседям: если в колонке Account 5 строк подряд один счёт — следующая префиллится тем же.
- Smart defaults: дата = вчера для серии, можно `Cmd+D` чтобы скопировать всю предыдущую строку.
- В правом нижнем углу — кнопка `+ Ещё 10 строк`.
- `Cmd+Enter` — submit всех валидных.

### 10.3 Autocomplete

| Поле | Источник |
|---|---|
| Title | Топ-50 уникальных `title` юзера, сортировка по частоте + recency. Latency < 50ms. |
| Category | Все категории юзера, отображаются с иконками. Free-text — создаёт новую (с подтверждением). |
| Account | Все счета, фильтрованные по совместимости с типом операции. |
| Note | Не autocomplete — free-text. |

UI: dropdown под полем, `↑↓` навигация, `Enter`/`Tab` выбирает, `Esc` закрывает. Highlight вхождений жирным.

### 10.4 Quick-recurrence из транзакции

- В History row context menu — `Сделать запланированной` → префилит форму `/events/new` суммой/категорией/счётом/днём из этой транзакции.

## 11. Состояния (loading / empty / error / success)

### 11.1 Loading

- **Skeleton** компоненты вместо спиннеров — те же блоки, что финальный UI, но `--surface-2` плашки с лёгкой shimmer-анимацией (`prefers-reduced-motion` отключает).
- **Optimistic UI**: при сохранении транзакции / редактировании ячейки сразу показываем результат, на ошибке — откат с toast.
- **Skeleton strict**: skeleton-блоки совпадают по высоте с реальным контентом, чтобы не было layout shift.

### 11.2 Empty

- **Empty state** — иллюстрация (геометрическая, в стиле дизайн-токенов; не sketch и не cartoon), заголовок «Тут пока пусто», описание, **CTA**.
- Empty `/history` без фильтра → CTA «Добавить первую» + «Импортировать».
- Empty с фильтром → CTA «Сбросить фильтры».
- Empty `/analytics/*` → «Накопите хотя бы 14 дней операций».

### 11.3 Error

- **Inline-валидация** в формах: красный текст под полем, `aria-invalid`, фокус на первое невалидное при submit.
- **Network errors**: top-toast `--neg` с Retry-кнопкой, не блокирует UI.
- **Server errors 5xx**: full-screen empty-state «Что-то пошло не так» + Retry + Report (открывает mailto или forms).
- **Conflict (409)**: модалка с diff и выбором версий.

### 11.4 Success

- Subtle toast `--pos` 2-3 сек: «Сохранено», «Импортировано 47», «Удалено 3 операции» с `Отменить (Cmd+Z)` ссылкой.
- Audio cue — нет (по умолчанию off).

### 11.5 Confirmations

- Удаление одной операции — без modal, оптимистично + Undo toast 30с.
- Удаление >1 / счёта / события — modal с обратным отсчётом 5с до активации кнопки `Удалить`.
- Удаление счёта с балансом > 0 — обязательная двойная проверка + ввод имени счёта.

## 12. Доступность и i18n

### 12.1 A11y

- **Контраст**: AA для основного текста, AAA для критичных цифр (балансы, суммы). Token `--text-3` (subdued) — ≥ 4.5:1 на `--bg`.
- **Keyboard nav**: всё функционально без мыши. Tab-order логичный: TopBar → Sidebar → Main → Context panel.
- **Фокус-trap** в modal (Radix даёт из коробки).
- **ARIA**:
  - `aria-label` на иконках без текста.
  - `aria-live="polite"` для toast и аналитических чисел.
  - `aria-sort` на sortable header'ах.
  - `aria-expanded`, `aria-controls` для collapsible.
  - `role="dialog"` + `aria-modal` на модалках.
- **Screen reader**: важная цифра (display) озвучивается с единицей: «один миллион двести сорок семь тысяч восемьсот двадцать рублей» (через `<span class="sr-only">` дублирование).
- **Reduced motion**: `prefers-reduced-motion: reduce` отключает shimmer, hover-lift, slide-transitions, оставляет fade.
- **Reduced transparency**: `prefers-reduced-transparency` заменяет `backdrop-blur` на solid `--surface-2`.

### 12.2 i18n

- Локаль одна — `ru`. Все строки в коде уже на русском.
- Числа: `Intl.NumberFormat('ru-RU')` через `formatRubles`.
- Даты: `date-fns/locale/ru`.
- Не делаем переключатель языков в v1.0 — но **не хардкодим** ru-locale, кладём в один модуль `lib/i18n.ts` для будущего.

### 12.3 Темы и контраст

- Pulse / Paper / Noir — каждая проходит AA по `--text` на `--bg`.
- Графики используют `--accent`, `--pos`, `--neg` — тестируем на color-blind симуляторах (Daltonize).
- Тонкие линии (`hairline`) — не несут информацию, только декорация.

## 14. Acceptance criteria

Десктоп считается готовым когда:

### 14.1 Производительность

- TTI на cold load на M1 + Chrome ≤ 1.5s.
- 60fps при scroll History с 10 000 строк (виртуализация).
- Inline edit отвечает за < 100ms (optimistic).
- Command palette открывается за < 50ms, поиск возвращает результаты за < 200ms.
- Бандл клиентского JS на главной < 250KB gzipped.

### 14.2 UX

- Юзер вводит 30 транзакций за 5 минут с клавы (paste-grid + autocomplete).
- 100% действий из мыши доступны с клавы.
- Ни один экран не показывает «вечный спиннер» — всё через skeleton с fallback-таймаутом 8с.
- Все формы — inline-валидируются.
- Optimistic UI на add / edit / delete транзакций.
- Undo в 30с после деструктивных действий.

### 14.3 Дизайн

- 3 темы работают пиксель-в-пиксель идентично (только цветами).
- Tabular-nums везде, где есть числа.
- Все цифры считаются по формулам §7, без расхождений.
- Все экраны проходят AA по контрасту.
- На `1024px` ничего не вылезает за viewport.
- На `2560px` контент не растягивается мутно.

### 14.4 Совместимость с мобилкой

- Тот же `lib/db/schema.ts`, те же engines, тот же auth.
- Темы — те же CSS variables.
- Никаких отдельных API для desktop.
- Юзер открывает один и тот же URL на мобиле и на ноуте — видит одни и те же данные.
