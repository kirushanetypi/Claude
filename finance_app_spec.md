# Финансовое приложение — спецификация

iOS-приложение (SwiftUI + SwiftData) для управления личными финансами: дебет, накопительный, кредитная карта Т-Банк, потребкредит Т-Банк. Финансовый календарь с прогнозом баланса.

> **Note (web port):** этот документ — оригинальная iOS-спека. Мы переносим бизнес-логику 1:1 в Next.js 15 + TypeScript. Слои `Views (SwiftUI)` / `SwiftData` заменяются на App Router + Drizzle/SQLite. Decimal в JS считаем через `decimal.js`, в БД храним в копейках (integer). Все остальные правила (грейс 26→19, аннуитет, прогноз) переносятся без изменений.

## 1. Сущности (модели данных)

### 1.1 Account (счёт)

```swift
enum AccountType: String, Codable {
    case debit          // основной дебетовый счёт
    case savings        // накопительный счёт
    case creditCard     // кредитная карта
    case loan           // кредит наличными
}

@Model
final class Account {
    var id: UUID
    var type: AccountType
    var name: String
    var balance: Decimal              // для debit/savings — остаток денег
                                      // для creditCard — текущий долг
                                      // для loan — остаток основного долга
    var createdAt: Date

    // только для savings
    var interestRate: Decimal?        // годовая ставка
    var interestPayoutDay: Int?       // день начисления процентов

    // только для creditCard (см. раздел 2)
    var creditCardSettings: CreditCardSettings?

    // только для loan (см. раздел 3)
    var loanSettings: LoanSettings?

    @Relationship(deleteRule: .cascade) var transactions: [Transaction] = []
}
```

### 1.2 Transaction (операция)

```swift
enum TransactionType: String, Codable {
    case income         // доход (зп, возврат и т.д.) — только на debit/savings
    case expense        // расход — с debit или creditCard
    case transfer       // перевод между счетами
    case interest       // начисление процентов (автоматическое)
    case loanPayment    // платёж по кредиту (специальный transfer)
}

@Model
final class Transaction {
    var id: UUID
    var type: TransactionType
    var amount: Decimal
    var date: Date
    var title: String
    var category: String?             // "еда", "транспорт" и т.д.
    var note: String?

    // для expense/income
    var account: Account?

    // для transfer — источник и получатель
    var fromAccount: Account?
    var toAccount: Account?

    // связь с запланированным событием (если это факт по плану)
    var scheduledEventId: UUID?

    // для loanPayment — разбивка
    var principalPart: Decimal?       // в тело долга
    var interestPart: Decimal?        // проценты
    var extraPayment: Decimal?        // досрочка сверху регулярного платежа
}
```

### 1.3 ScheduledEvent (запланированное событие)

```swift
enum RecurrenceRule: Codable {
    case once(Date)
    case monthlyByDay(Int)            // каждое N число
    case weekly(weekday: Int)         // день недели 1-7
    case custom(cron: String)         // на будущее
}

enum EventStatus: String, Codable {
    case planned                      // будущее событие
    case fact                         // исполнено, есть Transaction
    case skipped                      // пропущено вручную
}

@Model
final class ScheduledEvent {
    var id: UUID
    var title: String
    var baseAmount: Decimal           // базовая (ожидаемая) сумма
    var transactionType: TransactionType
    var accountId: UUID               // какой счёт затрагивает
    var toAccountId: UUID?            // для transfer
    var category: String?
    var recurrence: RecurrenceRule
    var isActive: Bool
    var autoGenerated: Bool           // сгенерировано системой (кредит/кредитка)

    // история фактов: месяц -> actualAmount
    // ключ формата "2026-05" -> factData
    var factHistory: [String: EventFact] = [:]
}

struct EventFact: Codable {
    var actualAmount: Decimal
    var actualDate: Date
    var status: EventStatus
    var transactionId: UUID?
}
```

> **Web port note:** `factHistory` (словарь `monthKey -> EventFact`) переносится в отдельную SQL-таблицу `event_facts(event_id, user_id, month_key, actual_amount, actual_date, status, transaction_id)` с уник-ключом `(event_id, month_key)` — для аналитики §7.6.

## 2. Кредитная карта — модель и логика

### 2.1 Настройки карты (Т-Банк Платинум)

```swift
struct CreditCardSettings: Codable {
    var creditLimit: Decimal = 100_000          // лимит (настраивается)
    var statementDay: Int = 26                  // день выписки
    var paymentDueDay: Int = 19                 // дедлайн оплаты (след. месяц)
    var annualRate: Decimal = 0.599             // 59.9% годовых
    var minPaymentRate: Decimal = 0.08          // 8% от долга
    var minPaymentFloor: Decimal = 600

    // состояние грейса
    var statementDebt: Decimal = 0              // зафиксирован 26-го
    var lastStatementDate: Date?
    var paidAfterStatement: Decimal = 0         // погашено после 26-го
}
```

### 2.2 Вычисляемые метрики карты

```swift
extension Account {
    var available: Decimal {
        guard let s = creditCardSettings else { return 0 }
        return s.creditLimit - balance
    }

    var toCloseGrace: Decimal {
        guard let s = creditCardSettings else { return 0 }
        return max(s.statementDebt - s.paidAfterStatement, 0)
    }

    var minPayment: Decimal {
        guard let s = creditCardSettings else { return 0 }
        return max(s.statementDebt * s.minPaymentRate, s.minPaymentFloor)
    }

    // прогноз % если грейс пропущен (упрощённо)
    var estimatedInterestIfMissed: Decimal {
        guard let s = creditCardSettings else { return 0 }
        // средневзвешенный период ≈ 45 дней
        return s.statementDebt * s.annualRate * 45 / 365
    }

    var graceStatus: GraceStatus {
        guard let s = creditCardSettings,
              let due = nextPaymentDueDate() else { return .none }
        let days = Calendar.current.dateComponents([.day],
                                                    from: Date(),
                                                    to: due).day ?? 0
        if toCloseGrace == 0 { return .closed }
        if days < 0 { return .overdue }
        if days < 3 { return .red }
        if days < 7 { return .yellow }
        return .green
    }
}

enum GraceStatus { case none, green, yellow, red, overdue, closed }
```

### 2.3 Операции по карте

|Операция                                                  |Эффект                                                                                   |
|----------------------------------------------------------|-----------------------------------------------------------------------------------------|
|Трата с кредитки (expense, account=creditCard)            |`balance += amount`                                                                      |
|Погашение с дебета (transfer debit→creditCard)            |`debit.balance -= amount`, `creditCard.balance -= amount`, `paidAfterStatement += amount`|
|Формирование выписки (26 число, автоматически)            |`statementDebt = balance`, `paidAfterStatement = 0`, `lastStatementDate = today`         |
|Начисление % (автоматически 20 числа если грейс не закрыт)|создаётся Transaction(.interest), `balance += interest`                                  |

### 2.4 Автособытия календаря для кредитки

Система автоматически создаёт/обновляет 3 события каждый месяц:

1. **Формирование выписки** — `statementDay` (26-е), тип `.interest` (служебное, amount=0)
1. **Напоминание закрыть грейс** — за 5 дней до `paymentDueDay` (14-е)
1. **Дедлайн грейса** — `paymentDueDay` (19-е)

## 3. Потребкредит — модель и логика

### 3.1 Настройки кредита (Т-Банк, текущий)

```swift
struct LoanSettings: Codable {
    var principal: Decimal = 350_000            // изначальная сумма
    var annualRate: Decimal = 0.365             // 36.5% годовых
    var basePayment: Decimal = 12_840           // регулярный платёж
    var paymentDay: Int = 1                     // 1 число каждого месяца
    var startDate: Date                         // дата выдачи
    var originalTerm: Int = 59                  // изначальный срок в месяцах
    var remainingTerm: Int                      // осталось платежей

    // состояние
    var paidThisMonth: Bool = false             // флаг сбрасывается 1-го числа
    var lastPaymentDate: Date?
}
```

### 3.2 Формулы

```swift
extension LoanSettings {
    var monthlyRate: Decimal { annualRate / 12 }

    // проценты в следующем платеже
    func interestInNextPayment(currentBalance: Decimal) -> Decimal {
        return currentBalance * monthlyRate
    }

    // тело в следующем платеже
    func principalInNextPayment(currentBalance: Decimal) -> Decimal {
        return basePayment - interestInNextPayment(currentBalance: currentBalance)
    }

    // пересчёт срока после досрочки (сохраняем платёж)
    // n = -log(1 - balance * i / P) / log(1 + i)
    static func recalcTerm(balance: Decimal, rate: Decimal, payment: Decimal) -> Int {
        let i = NSDecimalNumber(decimal: rate).doubleValue
        let b = NSDecimalNumber(decimal: balance).doubleValue
        let p = NSDecimalNumber(decimal: payment).doubleValue
        let n = -log(1 - b * i / p) / log(1 + i)
        return Int(ceil(n))
    }

    // переплата до конца срока
    func remainingOverpayment(currentBalance: Decimal) -> Decimal {
        return basePayment * Decimal(remainingTerm) - currentBalance
    }
}
```

### 3.3 Операции по кредиту

|Операция                                                  |Эффект                                                                                                                                       |
|----------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------|
|Регулярный платёж (transfer debit→loan, type=.loanPayment)|`debit -= payment`, разбивка на `interestPart`/`principalPart`, `loan.balance -= principalPart`, `remainingTerm -= 1`, `paidThisMonth = true`|
|Досрочка (transfer debit→loan с `extraPayment > 0`)       |`debit -= extra`, `loan.balance -= extra`, пересчёт `remainingTerm`                                                                          |
|Редактирование платежа                                    |`basePayment = newValue`, пересчёт `remainingTerm`                                                                                           |

### 3.4 Автособытия календаря для кредита

1. **Платёж по кредиту** — `paymentDay` (1-е) каждого месяца, сумма `basePayment`

## 4. Финансовый календарь и прогноз

### 4.1 Регулярные события (пример стартового набора)

|Событие          |Тип          |Счёт      |День|Сумма        |
|-----------------|-------------|----------|----|-------------|
|Зарплата основная|income       |debit     |5   |46 000 (base)|
|Квартира         |expense      |debit     |?   |67 000       |
|Платёж по кредиту|transfer→loan|debit     |1   |12 840       |
|Выписка кредитки |служебное    |creditCard|26  |—            |
|Дедлайн грейса   |служебное    |creditCard|19  |—            |

Пользователь может добавлять свои (подписки, связь, интернет и т.д.).

### 4.2 Логика прогноза

```swift
struct ForecastEngine {
    let accounts: [Account]
    let events: [ScheduledEvent]

    /// Рассчитать баланс всех счетов на конкретную дату в будущем
    func forecast(at targetDate: Date) -> [UUID: Decimal] {
        var balances = accounts.reduce(into: [UUID: Decimal]()) {
            $0[$1.id] = $1.balance
        }

        let today = Calendar.current.startOfDay(for: Date())
        let target = Calendar.current.startOfDay(for: targetDate)

        // собрать все события между сегодня и target
        let upcomingEvents = expandEvents(from: today, to: target)
            .sorted { $0.date < $1.date }

        for event in upcomingEvents {
            let amount = event.actualAmount ?? event.baseAmount
            applyEvent(event, amount: amount, to: &balances)
        }

        return balances
    }

    /// Развернуть рекуррентные события в конкретные даты
    func expandEvents(from: Date, to: Date) -> [ResolvedEvent] { ... }

    /// Применить событие к балансам
    func applyEvent(_ event: ResolvedEvent,
                    amount: Decimal,
                    to balances: inout [UUID: Decimal]) { ... }
}

struct ResolvedEvent {
    let eventId: UUID
    let date: Date
    let baseAmount: Decimal
    let actualAmount: Decimal?
    let type: TransactionType
    let accountId: UUID
    let toAccountId: UUID?
}
```

**Правила прогноза:**

- Если событие в статусе `.fact` — использовать `actualAmount`
- Если `.planned` — использовать `baseAmount`
- Если `.skipped` — игнорировать
- Прогноз процентов по кредитке добавляется как событие `.interest` если по расчёту грейс не закроется
- Регулярный платёж по кредиту автоматически разбивается на тело/% при прогнозе, балансы кредита и дебета меняются синхронно

### 4.3 Отображение календаря

- Вид месяца: на каждом дне — иконки событий, цветовая маркировка (доходы зелёные, расходы красные, дедлайны жёлтые/красные)
- Тап по дню → список событий этого дня + итоговый баланс на конец дня
- Линейный график «баланс дебета по дням» на месяц вперёд
- Алерт если прогнозный баланс уходит в минус

## 5. Логика отклонений от плана

Когда наступает дата события, пользователь подтверждает факт:

```swift
enum FactResolution {
    case confirmBase                          // получил ровно baseAmount
    case confirmActual(Decimal)               // получил/потратил X
    case skip                                 // пропустить в этом месяце
}

func resolveEvent(_ event: ScheduledEvent,
                  for monthKey: String,      // "2026-05"
                  resolution: FactResolution) {
    switch resolution {
    case .confirmBase:
        createTransaction(amount: event.baseAmount, ...)
        event.factHistory[monthKey] = EventFact(
            actualAmount: event.baseAmount,
            actualDate: Date(),
            status: .fact,
            transactionId: txn.id
        )
    case .confirmActual(let amount):
        createTransaction(amount: amount, ...)
        event.factHistory[monthKey] = EventFact(...)
    case .skip:
        event.factHistory[monthKey] = EventFact(
            actualAmount: 0,
            status: .skipped, ...
        )
    }
}
```

**Важно:** прогноз на **будущие** месяцы всегда использует `baseAmount`. Факт одного месяца не меняет base для других месяцев. Отдельно ведётся статистика отклонений для аналитики.

## 6. Архитектура

### 6.1 Слои

```
Views (SwiftUI)
  ↓
ViewModels (ObservableObject, @Observable)
  ↓
Services
  - AccountService         — CRUD счетов, пересчёт балансов
  - TransactionService     — создание операций, откат
  - ScheduledEventService  — CRUD событий, разворачивание
  - ForecastEngine         — прогнозы
  - CreditCardEngine       — логика грейса, выписок, процентов
  - LoanEngine             — графики, досрочки, пересчёт срока
  - NotificationService    — пуши о дедлайнах
  ↓
SwiftData (persistence)
```

> **Web port note:** `Views (SwiftUI)` → `app/(app)/**` (RSC + клиентские компоненты), `ViewModels` → Zustand-сторы для локального UI-стейта, `Services` → Server Actions поверх Drizzle, `SwiftData` → SQLite через `better-sqlite3` + Drizzle ORM. Чистые движки (`LoanEngine`/`CreditCardEngine`/`ForecastEngine`) — отдельные модули в `lib/engines/`, юнит-тестируемые без БД.

### 6.2 Пересчёт состояния

После любой операции (транзакции, изменения события) запускается `StateRecalculator`:

1. Пересчитывает балансы всех затронутых счетов
1. Обновляет `statementDebt` если сегодня `statementDay` и ещё не обновлялось
1. Сбрасывает `paidThisMonth` для кредита если новый месяц
1. Перегенерирует ближайшие события (90 дней вперёд)

Запускается также при старте приложения и при смене суток (background task).
